Problème
Le document n'offre qu'une lecture : la vue complète. Compter les fill d'une page fait traverser le pont Wasm à la vue entière de chaque élément pour lire un seul champ, à chaque nouvelle version (board-session.ts:637), ~32 ms sur 63 au cas S6. La vue d'un fill lit tous ses anneaux pour rendre trois nombres. ImageView recopie les réglages d'ImageParams à la main.
Solution
Une lecture du kind seul, exposée par le cœur, le pont et le faux cœur ; une lecture de fill qui s'arrête aux champs de la vue ; une vue d'image qui contient ses réglages au lieu de les recopier (forme sérialisée à garder : serde(flatten) rendrait une Map JS).
Bénéfice
Profondeur : l'appelant demande ce qu'il lit. Localité : une seule définition des réglages d'image. Tests : un cas simple de plus au contrat fake/vrai cœur.
Risque
Faible : contrat describe.each fake/vrai cœur ; budget du module principal (1 368 840 o sur 1,5 Mo).

Problème
La règle « remettre le type d'un Blob » existe dans container-io.ts et est réécrite trois fois dans platform/. Le nom de fichier d'une ressource refait slug avec un autre repli. baseName vit dans un hôte, messageOf dans un contrôleur, isEditable dans paste.ts, d'où un cycle clipboard ↔ paste. L'export PDF garde une Map de Blob que le magasin d'assets rend déjà.
Solution
Un ou deux modules feuilles, sans dépendance, pour ces petites règles ; slug paramétré par repli et longueur ; retrait de la Map redondante.
Bénéfice
Localité : une règle par sujet. Le cycle disparaît. app/ ne dépend plus d'un hôte pour une fonction générique.
Risque
Faible : vérifier la copie DAPF3 de l'export PDF avant de retirer la Map.

Problème
Union de boîtes et contour d'un élément sont privés dans query.rs, donc refaits ailleurs : snap_box recopie la boucle de bounds, zone.rs refait l'union et la cascade de element_geom, deux autres boucles min/max existent. Les lectures typées des traits, formes et textes vivent dans commands.rs. Aucun test ne vérifie que le contour d'un mur égale le contour de requête.
Solution
Sortir la géométrie d'un élément dans un module à elle, utilisé par les requêtes, les zones et le pot ; une boucle d'union partagée qui reçoit la règle de contour ; un test de parité.
Bénéfice
Localité : un concept, un fichier. Tests : la géométrie se teste sans Document complet ; la divergence wall_of / element_geom devient visible.
Risque
Moyen-faible : contours voulus différents (HC8-1, HG6) à préserver ; porte S6 ≤ 50 ms à remesurer.

Problème
Le lecteur ZIP rend des Blob que la bibliothèque reconvertit en octets (deux copies par entrée, jusqu'à 256 Mio) ; son mode est un 3e paramètre positionnel. remove("") vaut clear(). Le kind d'une ressource est une chaîne, et une erreur de programmation sort en « fichier endommagé ». placeGrid compare les grilles par JSON.stringify alors que le cœur rend déjà « inchangé » (commands.rs:1530).
Solution
Un lecteur de paquet qui rend des octets, options nommées ; une seule porte pour vider ; un kind de ressource fermé ; placeGrid qui s'en remet au cœur.
Bénéfice
Une copie mémoire de moins par entrée ; interfaces lisibles sans commentaire ; règle D38 tenue une fois.
Risque
Faible : module formats à 45 Ko de marge (décision 0263) ; gain iPad non mesuré.

Problème
ImageTarget est le contexte de pose de tout l'import mais vit dans le module image. Ajouter un type importable touche 5 à 7 fichiers : extensions, MIME écrits à la main par hôte, ordre implicite du registre, champ d'ImportDeps. Quatre gestionnaires restent dans import.ts ; cycle import.ts ↔ model3d-handlers.ts.
Solution
Un module « cible de pose » nommé pour son rôle ; chaque gestionnaire porte ses extensions, MIME et priorité ; listes des hôtes dérivées du registre ; gestionnaires sortis d'import.ts.
Bénéfice
Ajouter un type = un fichier et une ligne de registre ; cycle cassé ; import.test.ts (1024 lignes) réparti par gestionnaire.
Risque
Moyen : ordre de détection et filtres du sélecteur par hôte à garder identiques.

Non retenus (à surveiller)

  • workspace.ts (674 l.) et board-session.ts (769 l.) mêlent 5 et 7 responsabilités ; aucun constat ouvert ne les vise : découpage par morceaux, plus tard.
  • Ajout d'une commande ou d'un kind (enum Command, apply, pont, api.ts, fake-core.ts) : contrat fake/vrai décidé (docs/plans/usage-cadrage.md:132), non rouvert.
  • toolbar-host.ts:45 : infirmé pour app/ (déjà presetsOf à :83) ; reste toolbar.ts:666.

Ma recommandation

Commencer par A : seul gain mesuré chez l'utilisateur (recompte à chaque version, ~32 ms au cas S6), court, et il pose une lecture légère dont C profitera. B ensuite : sans risque, TypeScript seul, quatre constats. Pour fiabiliser d'abord le pot tout juste livré, C passe devant, pour son test de parité wall_of / element_geom.
